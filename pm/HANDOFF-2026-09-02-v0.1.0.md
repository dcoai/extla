## THE DAY THIS HANDOFF EXISTS TO EXPLAIN

A routine status review found **CI had been red on `main` for five consecutive merges** —
#64-#67 and #69, the whole *verification ledger* milestone — and nobody had noticed.

`#64` added `surfex` over a `git@` URL; the slim CI image has no `ssh`, so `mix deps.get`
failed in every `check`-stage job. **The damage was not the red badge.** `verify` never
started, so `mutation`, `tla-coverage-drift` and `tlc-corpus` reported **`skipped`, not
`success`**, for ten hours.

> **A skipped gate and a passing gate look identical in a merge request.** That is the same
> confusion between presence and evidence that `TLA_COVERAGE.md` exists to prevent one layer
> down. If you read one line of this handoff, read that one.

Restoring CI (#71) immediately exposed **two pre-existing defects that had merged blind**:

- **#77/#78** — `mix test` OOM-killed. Root cause: `liveness_test.exs` ran an *infinite* spec
  with `check_liveness: true` and no `max_states`, inheriting the default 1,000,000 and
  building a liveness graph over all of it **to assert a status was one of two atoms**.
  909 MB → 147 MB for that file; 940 MB → 728 MB for the suite.
- **#76/#79** — the workers-agree property. It asserted state *counts* that
  `ModelChecker.Parallel` never promised. Not fixed by #78, which is why it was not closed on
  that assumption.

## WHAT IS OPEN

**A. #85/#72 — the memory ceiling, and the merge gate behind it.** `main` OOM'd **again**
(#950) after #78's fix, so 728 MB is still marginal. The measurements that matter:

| Finding | Evidence |
|---|---|
| Not one test any more | `test/differential` 658 MB, `test/tla` 491 MB after #78 |
| Not concurrency | `--max-cases` 2/4/8 → 711/705/754 MB. Flat, measured twice |
| Not a retained graph | `differential_case.ex` keeps it deliberately, for `GraphAudit`, documented |
| **Allocator high-water** | `raft_election` alone: **132 MB live after GC, 315 MB RSS** |

**Every measurement so far has been of the numerator.** Nobody knows the ceiling — which is
exactly why #77 could be diagnosed, fixed, measured, and still leave `main` failing. **#86 has
merged and now prints the cgroup limit in every job log**; read it, put the ratio on #85, and
only then choose between raising the runner allowance (needs runner admin, outside this repo),
splitting `test/differential` into its own job (measured: worst job 728 → 666 MB, an 8.5% gain),
or ERTS allocator flags (**not recommended** — this project has already learned that a
memory/speed knob set on intuition measures worse; see `write_concurrency: :auto` below).

**#72 must not be enabled until `main` is reliably green.** Its branch
`issue-72-merge-gate` exists with the `.gitlab-ci.yml` comment **committed locally and
deliberately unpushed**, because that comment asserts the gate is on and it is not.

**B. #87 — property-directed slicing.** Extracted from #16. It is the *sound, automatic* form
of the `view` abstraction `spec/04-layer2-model-checker.md:733` already specifies and defers as
"easy to get wrong": derived from the property rather than declared by the author, so it cannot
drop a distinction the property needs. Unevaluated.

**C. #16 — stays `Research`, and one strand is blocked on a decision.** `pm-16` recommends
partial-order reduction as the biggest win, but **`spec/04:741` declares POR a non-goal.** That
conflict must be argued and the spec amended before POR can be proposed. The non-goal's stated
reason is about *Concuerror's* level (process interleavings), which is arguably not the same as
reduction over a spec's state graph — a real argument, but one to make explicitly.

## THINGS THAT WILL BITE

The previous handoff's list still holds in full — read it in `pm/closed/`, especially the
benchmarking traps (**read a wall time with the load average beside it, and interleave every
A/B**; `buffer` is too small to measure; `write_concurrency: :auto` is 7.6x slower). What today
added:

- **The `surfex` job-token allowlist is per-project and NOT inherited from the group.** If CI
  fails with `HTTP Basic: Access denied`, check `dco-tek/surfex`'s inbound allowlist before
  touching `.gitlab-ci.yml`. `dco-tek/extla` (id 178) was added on 2026-09-02.
- **`glab api` rejects the URL-encoded path form on POST/PUT** (`{"error":"id is invalid"}`) and
  needs the numeric project id. It *accepts* the encoded form on GET, so the failure reads like
  a permissions problem and is not one.
- **RSS is not live memory.** The BEAM held 315 MB RSS for 132 MB of live data in a
  single-shot script. Measure `:erlang.memory/1` **and** RSS; they answer different questions,
  and bounding concurrency cannot help with the second.
- **`Killed  mix test` is reported by GitLab as `script_failure`.** It reads exactly like a
  failing test. Grep job logs for `Killed` before concluding a test broke.
- **A commit that does part of an issue must say `Part of #N`, never `Closes #N`** — GitLab
  matched `Closes #83` inside `Closes #83 (part 1)` and closed the issue while part 2 was still
  in review.
- **Under workers, counts on a HALTED run are not comparable, and this is by design.**
  `Parallel.dispatch/2` feeds an `ordered: false` `Task.async_stream` into `Enum.reduce_while`,
  so a violation halts the reduce and discards unconsumed workers' contributions. **Verdict and
  counterexample length are the guarantee** (D-27); counts are not. Do not re-tighten
  `generated_models_test.exs`.
- **A test that inherits a default can be enormous by accident.** `max_states` defaults to
  1,000,000. On an unbounded spec that is a million states for an assertion about an atom.
  Every other `Unbounded` call site in the suite was already bounded — this was an outlier, and
  the bound now carries a comment saying so.
- **Ask what a document asserts that nobody checks.** Three documents were found stating things
  that were not true — the README (two phases stale), this handoff's predecessor (claimed
  `~/Projects/claude-tools/` did not exist; **it does, all eleven scripts**), and
  `.gitlab-ci.yml`'s header. The fix was not a gate: prose that is a *judgement* cannot be a
  golden, and a golden a human decides the meaning of is a gate that cannot fail. **Fewer places
  to drift beats a gate that cannot catch drift.**
- **A gate whose red path nobody has run is not known to be a gate.** `mix tla.coverage
  --check`'s two `Mix.raise` branches had never executed anywhere (#84). Its success path was
  covered by CI; its failure path by nothing.

## HOW THE WORK IS RUN

```bash
glab issue list                                    # the queue
/prop-eval <n>                                     # accept, and assign a milestone
/prop-break-down <n>                               # work items inherit that milestone
/start-work <n>                                    # In-Progress, branch issue-<n>-<name>
mix format && mix compile --warnings-as-errors && mix test && bin/tlc-expected --check
/submit-review <n>                                 # commit, MR, Review
/complete-review <n>                               # merge, close, close the milestone
```

```bash
MIX_ENV=prod mix compile --warnings-as-errors      # the library as a consumer gets it
MIX_ENV=prod mix hex.build                         # packaging check; `links` gap is expected
mix tla.mutants --check                            # the drift gate (CI, ~8.5 min)
MIX_ENV=test mix tla.coverage --check              # the ledger's HARD gate
mix tla.check Specs.X --workers 8                  # parallel safety; implies safety-only
mix run bench/search_profile.exs workers [entry]   # the 1/2/4/8 sweep
bin/tlc-expected --check                           # the oracle gate; CI runs it
/usr/bin/time -v mix test | grep "Maximum resident"  # peak RSS, when memory is in question
```

**Per-milestone worktrees ARE available** — `~/Projects/claude-tools/` exists with all eleven
scripts, contrary to what the previous handoff said. Use the main checkout anyway when only one
milestone is active; worktrees exist to parallelise *across* milestones and cost ~1.4 GB each.
